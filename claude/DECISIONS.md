# DECISIONS.md — 决策记录

> 记录关键取舍与原因，便于追溯。

## 已确认决策

### D1. 解析工具链（2026-10-04）
PDF 用 `pdfplumber`，DOCX 用 `python-docx`，CLI 用 `typer`，日志用标准库 `logging`。
**原因**：CONTEXT.md 明确指定，且避免重量级依赖，符合"轻量降噪"定位。

### D2. 定位边界：降噪而非还原排版
工具目标是提升文本质量、减少 AI 噪声，不是精确复刻原排版。标题层级/表格/公式均尽力识别，识别失败时降级为占位或原文连续文本。
**原因**：多栏/复杂排版的 PDF 全自动高保真解析成本高、易误伤正文，违背轻量定位。

### D3. 扫描版 PDF 处理策略
无文本层 PDF 仅写入 `【SCANNED DOCUMENT: 无法提取文本】` 标记；`--skip-scanned` 时完全跳过不生成 md。绝不引入 OCR。
**判定用两道**：先试用 pdfplumber 提取文本；仍为空再兜底检查页面是否存在任何文字对象；确实无文字层才标 SCANNED。避免加密/仅图块/损坏文件被误判为正常文本。
**原因**：CONTEXT.md 明确约束，本版本不做图片文字识别，避免依赖膨胀；双层判定降低误判率。

### D4. 多栏检测（CONTEXT.md 修订时新增）
按页面文字 x0 坐标聚类识别单栏/多栏；多栏时按栏切分、按栏序输出，避免左右栏逐行交错。可用 `--no-columns` 关闭。
**原因**：原需求未覆盖多栏，而批量处理真实期刊库中双栏常见；当前 samplepapers 全为单栏故不受影响，但需为真实世界兜底。默认开启、可关闭，低风险。

### D5. 页眉页脚剔除的边界
仅剔除**跨页重复出现**的页眉/页脚/页码行；**第 1 页不处理**，保护题目/期刊名/DOI/作者等元数据。
**原因**：期刊第 1 页页眉即文章身份信息，一刀切删会丢失引用所需元数据。

### D6. 断字合并的保守规则
仅当"行尾为连字符 + 下一行以小写字母开头"时合并（`meth-\nod→method`）；真连字符词（`self-referential`）保留。
**原因**：naive 合并会破坏真连字符词，保守规则在保证词完整性与合并效率间取平衡。

### D7. 参考文献切除前校验
定位到 References 标题后，校验其后内容符合参考文献模式（numbered/年份/作者[et al.]）才切割；否则视为不可靠、不切。
**原因**：正文中可能先出现 "Reference to..." 等字样，直接切会造成误伤；模式校验降低风险。

### D8. 验收用可测计数器
以"残留页码行数 / 跨页重复页眉行数 / 过度粘连超长行数趋近 0 + 报告计数自洽"作为客观兜底，辅以单元测试覆盖边界。
**原因**："优化版 Markdown"主观无标准，需可跑可测的验收落点。

### D9. 断字合并的最终取向（兼容 CONTEXT 显式示例，取代 D6）
统一按"行尾连字符 + 下行小写开头"合并去连字符（`meth-⏎od→method`），**不再区分**软断字与真连字符。代价：恰好在连字符处折行的合法复合词（`self-⏎referential`）会被归一化成 `selfreferential`。
**原因**：CONTEXT.md 4 给出硬示例 `meth-⏎od→method`，规范高于我的 D6；无词典无法可靠区分二者。该局限记入 README 局限 1 与 PENDING #（待后续用断字词典根治）。

### D10. 多栏切分须在“词级”进行（修复核心 bug 的记录）
先对全页文字按 x0 中心做密度直方图找 gutter、把词划归各栏，**再**组行；绝不先组行再切栏。早期实现先组行导致左右栏同基线时被熔成一行（标题/落款与正文交错、词被粘连），已重构修正。
**原因**：单栏两栏同基线是常见形态；按 line 切栏必然失败，按 word 切栏才稳健。

### D11. 并行 + 解析缓存（速度升级）
用 `ProcessPoolExecutor` 按 `--workers` 并行“解析+清洗”（worker 返回可序列化结果，主进程统一写文件/汇总）；`--cache <dir>` 把每篇 PDF/DOCX 的解析脚手架按“路径+大小+mtime+布局旗标”缓存成 pickle。实测同旗标 `--overwrite` 重跑 **0.63s vs 冷跑 12.7s（约 20×）**。
**缓存 key 含 `--no-table/--no-columns`**：改布局旗标会重新解析；改 `--strip-reference` 等清洗旗标不触发重解析（这是一处已知取舍，见 PENDING）。
**原因**：批量文献库量大时解析是唯一瓶颈；并行吃多核，缓存吃“重跑复用”。

### D12. 输出位置参数化 + 命名规范
新增 `--out-mode`：`1`=输出到源文件同目录，`2`=全部拍平进 `--dest`，`3`=镜像子目录进 `--dest`（默认）。所有位置输出统一命名 `tomd_<源文件名>_<pdf|docx>.md`。
**原因**：用户明确要求“一键转换 + 命名 + 位置参数化”；`3` 保持原有镜像行为作默认、向后兼容，`1/2` 覆盖“就近输出/拍平集中”场景。
